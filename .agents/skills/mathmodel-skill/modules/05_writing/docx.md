# Module 05A：可选 DOCX 审阅分支

DOCX 仅在用户明确要求 Word 审阅、批注、协作或特定提交格式时启用。它是可选审阅载体，不是默认流程阶段，也不是 LaTeX 的前置事实源。

正文的**问题重述、问题分析、模型假设、符号说明、模型推导、核心模型收束、求解、结果解释、命题、模型评价、引用证据和语言风格**统一服从：

- `modules/05_writing/latex.md`：正文结构与表达权威；
- `core/writing_reasoning_contract.yaml`：跨竞赛推理、规则等级、命题预算和 Citation Evidence 权威；
- 中文国赛（CUMCM）论文写作与提交检查的补充口径读取 `packs/competition/cumcm.md`，其中用户提供资料与当届官方规则严格区分。

本模块只规定 Word 审阅载体、排版和迁移差异，不复制第二套正文规则。

## 一、进入门槛与事实源

写作前必须读取项目根目录最新版 `模型论文框架.md`，再从标准工作簿复核核心数值。框架负责当前模型语义、结构选择、命题与证据位置；工作簿负责数值事实。

若框架 stale、结果摘要非 current、模型/命题/图表与工作簿冲突，停止 DOCX 写作并返回上游修正。不得依靠聊天记忆重新拼接已删除的旧模型、旧参数、旧命题或旧结果。

用户已人工修改 DOCX 时，以最后上传版本为唯一底稿；不得用更早版本覆盖其人工排版和批注处理结果。

## 二、Word 专属排版规则

- 中文宋体、英文 Times New Roman、小四；数学变量使用公式环境排版，向量或矩阵需要强调时使用粗斜体；
- 两端对齐、段前后 0、首行缩进 2 字符、1.5 倍行距；若用户明确按其提供的内部资料排版，则摘要可采用固定值 22--24 磅或 1.25--1.5 倍行距，正文按当前模板统一，不混用多套间距；
- 一级标题居中黑色，禁止默认蓝色标题；
- 表格使用 Word 原生三线表，**表题在表格正上方**；正文表格保持精炼，数据过多时移附录；
- 数值与短文本单元格默认水平、垂直居中，长文字说明列按可读性左对齐；
- 图片整体居中，**图题在图片正下方**；图片以清晰可读为准，不直接使用低清截图替代原图；
- 图内可保留简洁 MATLAB `title/sgtitle`，Word 图题承担正式图号和图名，两者不逐字重复；
- 行内短公式嵌入正文；重要、较长或后文需要引用的公式单独居中并连续编号；
- 正文不堆完整代码，复杂算法只保留必要的分阶段步骤、伪代码或流程图，完整程序放附录/支撑材料；
- 摘要、正文、参考文献、附录按比赛模板要求分页；中文国赛是否设置目录、英文摘要、结论章等按当届官方模板和 `packs/competition/cumcm.md` 的来源分级处理；
- 内部 QA 表、批注和修订痕迹在正式迁移/提交前清除。

## 三、Word/WPS 自动编号与交叉引用

按用户提供的论文写作资料，图、表、公式和正文引用不得依赖手工编号维护。

### 3.1 图

1. 选中图片，使用【引用 → 插入题注】；
2. 标签选择或新建“图”，题注位置放在所选项目下方；
3. 若模板采用章节式编号，在【编号】中按模板设置章节号；
4. 正文“见图 XX”位置使用【引用 → 交叉引用】，引用类型选“图”，插入对应题注的标签和编号。

### 3.2 表

流程与图相同，但标签为“表”，题注位于表格上方。正文采用“如表 XX 所示”等自然引用，不手输固定编号。

### 3.3 公式

公式保持居中、编号靠右。可使用题注法，也可用无边框表格实现中间公式居中、右侧编号右对齐；无论采用哪种载体，正文均通过交叉引用插入公式编号。

### 3.4 全局更新

增删图、表或公式后，在 Word/WPS 中全选全文并更新域（通常为 `Ctrl+A` 后 `F9`；部分笔记本需 `Fn+F9`）。若单个引用未刷新，更新对应域后再检查导出 PDF 中的编号和引用是否完整。

## 四、命题与证明在 Word 中的呈现

命题数量和准入不在本模块定义。0--4 是 reasoning contract 的默认正文阅读预算，超过预算时按实际数学作用说明必要性，不自动否决。

Word 只负责呈现：

- 命题正文与短证明置于同一个外框；
- 证明以黑体“证明：”开头；
- 外框白底细边、无阴影和大面积底色；
- 框内不嵌套第二层边框；
- 原则上保持整框同页，长技术证明移附录而不是缩小字号硬塞；
- 框后正文说明命题对降维、约束、候选域、可行性、阈值、边界或模型必要性的实际作用。

证明长度和是否编号属于写作 Recommendation；Word 不把“3--8 行”或“2--6 步”当成硬格式检查。

## 五、图表与证据审阅

DOCX 人工审阅重点检查：

- 核心图表是否在邻近正文中显式引用编号；
- 图表解释是否写出主要趋势/关键数值和模型含义，而不是只靠题注；
- 表格、图、正文关键数字是否与当前工作簿一致；
- 图内标题、正式图题、正文解释是否分工清楚；
- 当前 Citation Evidence 是否在正文实际出现，不为凑参考文献数量放无用途引用；
- 中文国赛稿件若采用用户提供资料的结构，是否能在各问末尾直接回答设问，并在需要时给出误差、敏感性、稳健性或对比证据。

## 六、结构修改与框架同步

DOCX 中若只是字体、间距、换页和题注位置调整，不修改模型框架。

若人工审阅改变了以下项目，则同步更新完整 `模型论文框架.md`：

- 章节结构或共享基础位置；
- 命题位置、保留/删除状态；
- 图表证据位置；
- 当前结论的证据映射；
- Citation Evidence 使用位置。

框架只记录本项目当前选择和事实，不复制 Word 排版规范。

## 七、输出与验收

输出前执行 `templates/writing/docx_check.md`。正式 DOCX 交付至少包括：

- 可编辑 `.docx`；
- 完整最新版 `模型论文框架.md`；
- 明确的待补项及其前置条件；
- 需要迁移到 LaTeX 的图、表、公式、命题、引用和交叉引用。

DOCX 的内容验收消费 writing authority；Word 特有的字体、原生表格、题注、自动编号和可编辑性由本模块负责。
