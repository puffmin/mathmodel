# CUMCM 国赛适配器

- 最终中文论文默认使用 `templates/latex/cumcm/cumcmthesis/`；
- 摘要覆盖所有小问，写方法、关键数值和结论；关键词通常取 3--5 个、最多不超过 6 个，优先使用真实主方法和研究对象，不写 Python、MATLAB 等实现软件名；
- 重视题意覆盖、机制解释、模型合理性、结果可信、创新适度和附件复现；
- 正文不堆代码，完整代码放附件；
- 图表、表格、公式和参考文献按国赛模板统一；
- 不调用 `legacy/writing_phrase_corpus/` 套句，写作以本题证据为核心。

## 用户提供的中文国赛论文写作口径

本节吸收用户提供的国赛论文写作资料，仅作为当前 Skill 的中文国赛写作与提交检查口径；`config/competition_profiles.yaml` 中当届官方规则的 `verification_status` 仍保持独立，未核验时不得把本节改写成“官方已确认要求”。

### 论文结构

按该资料组织时，正文主线为：

```text
题目
→ 摘要、关键词
→ 一、问题的提出
   ├─ 问题的重述
   └─ 研究背景：研究意义 + 参考文献综述
→ 二、问题的分析
→ 三、模型假设
→ 四、符号说明
→ 五、建模与求解
→ 六、模型的检验 / 敏感性分析
→ 七、模型的评价与推广
→ 八、结论与建议
→ AI 工具使用声明
→ 参考文献
→ 附录
```

各问的“建模与求解”内部按真实题型组织，但应形成“数据处理（确有需要时）→ 模型建立与必要推导 → 参数与求解方法 → 计算结果 → 结果分析 → 逐项回答设问 → 必要的检验或修正”的闭环。模型不能只剩纯文字说明；复杂算法需要用可恢复计算逻辑的分阶段步骤、伪代码或流程图表达，完整程序仍放附录或支撑材料。

### 摘要与关键词

- 题目不要直接照抄赛题名称，可围绕“基于 ×× 方法的 ×× 问题”或“×× 问题的 ×× 模型”重构；实际采用的方法仍需通过 Title Claim Gate 与正文和结果证据闭合。
- 摘要要独立、完整、精炼，交代研究目的、方法、成果和结论；不放图、表、注释和复杂公式，不用参考文献结论替代本文结果，避免第一人称主观评价。
- 摘要先用短段交代全文对象和总体路线，再按问题一、问题二、问题三逐问写“方法/模型 → 关键数值结果 → 直接结论”；末尾可概括模型检验、误差、稳定性、敏感性，或模型优缺点、改进与推广。
- 关键词通常取 3--5 个、最多不超过 6 个，用统一分隔符；优先选择核心方法和研究对象，避免过宽泛的普通词，不写软件名，且与标题互补而非机械重复。

### 正文、结果与检验

- 问题重述用自己的语言压缩赛题背景、已知条件、数据范围和全部待求任务，逐问列清输出，不直接复制冗余题面。
- 研究背景分为研究意义和参考文献综述，资料中的经验篇幅分别约为 200--400 字、200--500 字；这是写作建议，不作为机器硬性字数门槛。
- 问题分析说明核心矛盾、目标、约束、问题类型、各问难点、数据特点、可行求解路径以及模糊条件如何引出后续假设，承担承上启下作用，不提前堆正式结果。
- 模型假设逐条服务建模，并说明合理性；符号表统一列出高频变量、参数、下标含义和单位，局部符号在首次出现处说明。
- 建模时保留必要推理、推导和演算，明确目标函数、约束、状态关系或判定关系；求解时说明参数如何确定、具体取值、算法步骤和计算结果。
- 结果分析不能只重复表格数字，要从图表提取单调性、极值、最值、拐点或其他真实结构特征，并解释其题目含义；随后逐项回答赛题提出的每个问题，随时间变化的量可用时间变化曲线支撑。
- 模型检验可按实际需要采用误差分析、参数敏感性、稳健性或多模型对比；可通过参数扰动、随机误差或其他真实验证检查结果稳定性。模型评价与检验分开，优点、缺点、改进和推广均需对应当前模型事实。
- “结论与建议”集中汇总所有子问题最终结论，逐条对应赛题提问，并结合实际场景给出确有模型结果支撑的落地建议，最后概括研究价值。

### 图表、公式、参考文献与附录

- 图必须编号和命名，图题在下；表必须编号和命名，表题在上，正文表格优先三线表，大表移附录；图表均需在正文中被明确引用和解释。
- 行内短公式直接嵌入文字；重要、较长或需要后文引用的公式单独居中并编号。图、表、公式和参考文献编号不得手工维护，使用 Word/WPS 题注与交叉引用或 LaTeX `\label`、`\ref`、`\eqref` 自动关联。
- 参考文献数量以实际使用为准，资料指出数模论文 3--5 篇即可、更多也可以；正文必须有真实引用。书籍、期刊、学位论文和网页分别按 `[M]`、`[J]`、`[D]` 与网页格式整理。
- 附录另起页，包含支撑材料文件清单、AI 工具使用详情、完整可运行源代码和必要数据/中间图表。若论文确实没有使用程序，应明确写明“本论文没有用到程序”。程序、论文结果与支撑材料必须一致。

### 资料中的版面与提交检查项

按用户提供资料检查中文国赛稿件时，同时核对：摘要页开始连续页码、无目录、无英文摘要、正文从摘要到参考文献不超过 30 页、附录页数不限、不得出现学校/姓名/队伍等身份信息、外部资料有正文引用与参考文献、支撑材料和论文结果一致、程序完整可运行。资料同时说明字体和行距没有统一强制值，因此具体载体优先服从当届官方模板与当前模块的排版设置；上述年度提交项只有在官方来源另行核验后，才写入 `edition_rules` 作为官方 Hard 规则。

## 用户提供的学生提交前自查清单

本节对应用户提供的《全国大学生数学建模竞赛论文自查清单》。资料定位是：提交论文前系统排查常见疏漏与规范性问题，建议由非论文主笔队员逐项核查，所有勾选项确认无误后方可提交。以下项目作为 CUMCM 终审/提交前自查内容使用；资料中“通常、一般”等数量建议按 Recommendation 处理。资料将第六类标注为“2026 年新规”，在 `competition_profiles.yaml` 未完成官方来源核验前，只保留该来源标注，不自动提升为当届官方 Hard 规则。

### 一、摘要撰写

- 摘要是否避免了空话套话（如“深入分析”“取得良好效果”等），有实质性内容？
- 摘要是否给出了模型优化后的具体数值结果，而非仅罗列模型名称？
- 摘要是否对使用的核心方法进行了简要说明，而非堆砌术语？
- 摘要字数是否控制在合理范围内（一般不超过 500 字）？

### 二、模型假设

- 各项假设是否有合理依据，而非凭空设定（如“数据无误差”等不切实际的假设）？
- 假设是否与实际问题场景相符，没有遗漏关键假设导致逻辑断层？
- 假设条数是否适中（一般 3--6 条），既不过少也不过冗长？

### 三、模型建立与求解

- 模型推导过程是否完整清晰，没有跳步使用“显然可得”等含糊表述？
- 求解工具（MATLAB/Python/SPSS 等）是否说明了具体调用的函数、参数设置及选用理由？
- 是否对求解结果进行了误差分析、灵敏度分析或稳定性分析？
- 模型结果是否与实际情况或基准方法进行了对比验证？

### 四、结果分析与结论

- 结果分析是否解释了数据背后的实际意义，而非仅罗列数据？
- 是否讨论了模型的局限性和适用场景，并提出改进方向？
- 结论是否明确醒目，包含必要的定量结果，而非让评委“挖宝”？
- 结论是否与摘要中的结论一致，没有前后矛盾？

### 五、排版格式与学术规范

- 图表是否清晰美观，有编号、标题，坐标轴有单位，图例完整？
- 公式是否统一格式，编号连续，没有混用多种样式？
- 同一变量/符号在全文中是否大小写一致、含义统一？
- 参考文献引用格式是否统一（正文引用方式与参考文献列表格式一致）？
- 是否避免了百度百科等非学术来源的直接引用？
- 摘要中是否没有违规引用文献？

### 六、支撑材料与 AI 工具使用（资料标注：2026 年新规）

- 是否已在论文正文附录中列出了支撑材料文件列表？
- 源程序代码是否完整且可运行，运行结果与论文内容一致？
- 自主查阅的数据资料是否已整理放入支撑材料？
- 如使用了 AI 工具，是否已生成“AI 工具使用详情.pdf”文件？
- “AI 工具使用声明”是否已放在参考文献之前？
- 支撑材料压缩包内是否已彻底清除所有与参赛队相关的身份信息（队号、姓名、学校等）？
- 提交前是否已重新生成支撑材料文件的 MD5 码并上传？

### 七、匿名性检查

- 论文正文、附录、支撑材料的所有文件（含文件夹名、文件名、文档属性）中是否均未出现参赛队任何身份信息？
- 图表、代码注释中是否未意外包含姓名或学校信息？

### 自查总评

终审时保留该清单的收口动作：记录自查人（队号）、自查日期、主要问题汇总和改进计划。该信息属于内部自查记录，不因清单存在而自动进入赛事官方提交包。
