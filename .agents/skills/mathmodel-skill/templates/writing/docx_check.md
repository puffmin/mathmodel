# HSK DOCX 草稿统一检查表

本表是执行检查单，不是规则权威。正文逻辑以 `modules/05_writing/latex.md` 和 `core/writing_reasoning_contract.yaml` 为准；Word 排版以 `modules/05_writing/docx.md` 为准。中文国赛若采用用户提供的内部论文写作资料，同时读取 `packs/competition/cumcm.md`。

检查结果只用于内部修改，不机械进入终稿正文。

## 1. 当前框架与事实一致性

| 检查项 | 是/否 | 备注 |
|---|---|---|
| `模型论文框架.md` 是否存在且为 current |  |  |
| 框架是否只保留当前有效模型、参数、Formula/Algorithm Trace、命题、结果、Citation Evidence 和图表映射 |  |  |
| Terminology Registry、Numeric Profile、Title Claim 与 Paper Fragment 状态是否与当前项目一致 |  |  |
| `stepwise/pseudocode` 小问是否存在 current Algorithm Trace，`not_needed` 是否没有装饰性 Algorithm 1 |  |  |
| 具体数值是否从已验收工作簿复核，而非只抄框架摘要 |  |  |
| 已求解/深化小问是否有 current 结果摘要 |  |  |
| semantic revision、stale 与当前代码/工作簿是否一致 |  |  |
| 正文是否没有恢复框架已删除的旧模型、旧参数、旧算法、旧命题或旧结果 |  |  |

## 2. 正文结构与证据

> 以下项目按 writing authority 的 Hard / Default / Recommendation 分级检查；Default 偏离有理由即可，不按模板机械判错。

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 问题重述是否能恢复研究对象、关键条件、数据范围和全部待求输出，且不是直接复制冗余题面 |  |  |
| 中文国赛采用用户提供资料时，研究背景中的研究意义与参考文献综述是否只保留对本题建模有作用的内容 |  |  |
| 问题提出与问题分析是否职责不同 |  |  |
| 问题分析是否写出本题真实难点、对象关系、目标/约束、问题类型和建模抓手，并为必要假设铺垫 |  |  |
| 假设是否服务于变量、约束、目标、分布、状态或边界，并说明合理性 |  |  |
| 符号表是否统一列出高频变量、参数、下标含义及必要单位，局部符号是否在首次出现处说明 |  |  |
| 假设、符号和共享基础是否清楚且无重复定义 |  |  |
| 核心公式是否有可恢复的 Source → Derivation → Destination |  |  |
| 各问核心模型收束是否与框架 `required / inline / not_applicable` 状态一致 |  |  |
| 模型建立是否包含必要数学关系、推理或推导，而不是只剩纯文字说明 |  |  |
| 求解段是否从当前模型结构解释算法、参数来源/取值、初始化或终止条件 |  |  |
| 算法流程是否按 `not_needed / stepwise / pseudocode` 自适应，而非每问机械设置伪代码 |  |  |
| `stepwise/pseudocode` 是否能沿 Algorithm Trace 追溯到公式/命题/约束、真实 Python 与工作簿结果或验证证据 |  |  |
| 主结果是否包含关键数值/图表、比较、机制和题目回答 |  |  |
| 结果分析是否从真实图表提取趋势、单调性、极值、最值、拐点或其他结构特征，而不是逐格复述数字 |  |  |
| 各问是否逐项回答赛题提出的每一个问题；随时间变化的量在需要时是否有时间变化曲线等证据 |  |  |
| 深化证据是否明确 target claim，并记录 `support / modify / reject` 与 required action |  |  |
| 多方法验证是否同时检查适用的数值一致性与结构一致性 |  |  |
| 模型检验与模型评价是否分开；误差、敏感性、稳健性或对比分析是否真正证明对应主张 |  |  |
| 中文国赛采用用户提供结构时，集中“结论与建议”是否逐条汇总子问题最终答案，并只提出有结果支撑的实际建议 |  |  |
| 独立结论章、特殊章节等 Default 偏离是否在框架或竞赛 Pack 中有依据 |  |  |

## 3. Algorithm Trace、命题与证明

| 检查项 | 是/否 | 备注 |
|---|---|---|
| Algorithm Trace 的输入/状态、核心操作、停止条件、输出与呈现模式是否完整 |  |  |
| 论文算法是否写数学对象/控制逻辑，没有搬入 DataFrame、文件路径、日志、异常捕获或并行池等工程细节 |  |  |
| 复杂算法若正文仅写一句“采用某算法求解”，是否已补足必要的分阶段步骤、伪代码或流程图 |  |  |
| 算法语义修改后旧 Trace、正文算法块及依赖 paper fragment 是否已 stale/重写 |  |  |
| 命题是否承担等价、降维、候选域、可行性、阈值、边界或解结构等实际作用 |  |  |
| 是否已删除变量定义、题意复述、直接代数变形型“伪命题” |  |  |
| 每个命题的前提、定义域/参数范围和结论是否完整 |  |  |
| 是否未用有限实验、交叉验证或求解器状态冒充数学证明 |  |  |
| 证明后是否说明下游模型/计算作用；若改变算法步骤，是否有对应 Algorithm Trace 锚点 |  |  |
| 命题正文与短证明是否位于同一外框 |  |  |
| 长技术证明是否按需要移附录 |  |  |
| 当前命题数若超过默认 0--4 预算，是否已有不可合并/不可移附录的必要性说明 |  |  |
| 模型、参数或约束变化后相关命题是否重新核验 |  |  |

> “3--8 行”“2--6 步”等仅为 Recommendation，不作为否决条件。机器或有限数值实验不能替代数学证明，也不能仅凭伪代码文字证明算法正确或收敛。

## 4. 摘要、标题、关键词、Citation Evidence、术语与数值展示

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 标题是否没有直接照抄赛题名称，且标题中的主方法/机制通过 Title Claim Gate |  |  |
| 摘要是否覆盖所有小问，并按实际情况写清方法/模型、关键数值结果和直接结论 |  |  |
| 摘要是否保持独立、精炼，不放图、表、注释和复杂展示公式 |  |  |
| 中文国赛采用用户提供资料时，摘要末尾是否按需要概括检验/误差/稳定性/敏感性或模型优缺点、改进与推广 |  |  |
| 关键词是否通常为 3--5 个、最多不超过 6 个，且使用统一分隔符 |  |  |
| 关键词是否优先使用真实主方法和研究对象，不写 Python、MATLAB 等软件名，不用过宽泛普通词替代真实关键词 |  |  |
| 外部经验参数、数据、领域事实、非显然标准定理和既有研究比较是否有 citation |  |  |

| 引用标准定理时是否核验本题条件 |  |  |

| 是否没有为凑数量而保留的无正文用途参考文献 |  |  |
| 同一技术量是否坚持 Terminology Registry 的 canonical term，没有因润色机械换词 |  |  |
| 易混术语的定义、符号、单位和范围是否分离 |  |  |
| 核心答案精度是否服从题面/官方/评分口径及 Numeric Profile，没有为“简洁”擅自降精度 |  |  |
| 百分比/百分点、单位、科学计数法、置信区间和坐标/时间精度是否一致 |  |  |

## 7. Title Claim、模型评价与语言

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 选定标题中的研究对象/主方法/机制/贡献是否在核心问题、正文、结果证据、摘要和关键词中闭合 |  |  |
| 模型优点是否有机制/验证证据，而非“简单、精度高、易推广”万能句 |  |  |
| 模型缺点是否说明影响哪个结果或边界 |  |  |
| 改进方向是否针对已指出的缺点，推广是否说明实际可迁移场景 |  |  |
| 优缺点条目数量是否由实际模型决定，没有机械数量关系要求 |  |  |
| 正文是否减少“本文/本问/该模型”连续段首 |  |  |
| 是否没有连续多段无真实冲突的否定/转折 |  |  |
| 是否删除对象替换后仍成立的模板段、元话语和算法百科 |  |  |
| 主要段落是否通过 Paragraph Necessity Test：删除后若不损失题意、机制、数学关系、求解依据、证据或必要边界，则删/并/移附录 |  |  |
| 是否保持规范、朴素、证据驱动，而非故意病句或机械同义词替换 |  |  |

## 9. 分级结论

- Hard/事实或结构错误：必须修复；
- Default 偏离：记录理由并人工确认；
- Recommendation：作为质量优化，不阻断迁移。
